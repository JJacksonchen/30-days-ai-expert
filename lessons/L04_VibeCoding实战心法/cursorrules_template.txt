# 项目 AI 施工守则 (.cursorrules / CLAUDE.md 通用模板)

## 1. 核心工程红线
- 严禁硬编码任何 API Key、数据库密码或密钥，统一从 `.env` 环境变量读取。
- 严禁未经询问擅自删除已有功能、重构无关文件或随意引入冷门重型依赖库。
- 涉及用户鉴权、支付扣费、数据删除的改动，必须明确列出改动文件与安全边界等待人工确认。

## 2. 开发与验收标准
- 每次只专注完成当前 1 个小里程碑任务（查看 `PLAN.md`），不擅自发散。
- 优先使用严格类型约束（TypeScript strict / Python type hints），保证类型检查零报错。
- 每实现一个新功能或修复一个 Bug，必须补充对应的自动化测试并实际运行至全部通过（全绿）后，再汇报完成。

## 3. 沟通与回滚
- 动手改代码前，先用 3 句话说明你的改动方案和涉及文件列表。
- 如遇连续 2 次尝试无法解决的报错，停止打补丁，列出根因假设与可选方案等待决策。
